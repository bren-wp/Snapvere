## Rollback preflight follow-up

Uncommitted gallery recovery now preflights both original/staged pairs before restoring either. If a thumbnail destination is occupied or either identity conflicts, preserve both staged members and the durable journal. Each restore still rechecks its member and uses no-replace rename. Added a restart regression preserving an unrelated thumbnail and both staged members until the conflict is resolved. Fresh native tests are required. This is not atomic multi-file rollback, does not remove pathname TOCTOU or inode reuse, and does not close high-severity S-02.

## Windows handle-bound rename follow-up

Windows staging and restoration now request FileRenameInfo on the same verified DELETE-capable file handle, with replacement disabled. The previous pathname-only MoveFileW step is removed; ancestor pinning and post-rename validation remain. The variable-length UTF-16 request uses the generated Windows ABI layout, bounded length and aligned zero-initialized storage (see [Microsoft API contract](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)). Added cross-platform replacement/no-overwrite regression and Windows sharing-lock regression. Native acceptance is pending. Linux rename and unlink remain pathname-based, file identity reuse and directory durability remain open; S-02 stays a release blocker. This does not claim zero data loss or a complete native memory audit.

## Versioned leaf fingerprint and Linux descriptor lifetime

New journal leaf values use a v3 fingerprint composed of native file ID, size, last modification time and creation time when exposed by the filesystem; the database schema remains v2 and parent identity format is unchanged. Older inode-only pending records are retained for manual recovery, not automatically reclassified or deleted. New tests cover in-place content changes and old committed journals. Linux keeps the verified file open across rename/unlink and checks the resulting identity/link count; this prevents immediate inode reuse during that operation and detects some substitutions. It cannot provide identity-conditional unlink or undo deletion of a substituted pathname. Timestamp metadata can be manipulated and creation time may be unavailable. S-02 remains high and open; physical recovery, legacy recovery UX, adversarial same-user races and fresh native CI remain mandatory.

Four isolated local Linux filesystem probes passed: identity/size/mtime stability across rename; zero links with a still-readable open descriptor after unlink; detection of a substituted-path unlink (the original descriptor retained one link, but the replacement had been deleted); and detection of a length change on the same inode. These Python/OS probes validate the underlying kernel observations only, not the Rust implementation or physical ext4/btrfs/NTFS acceptance. Rust/Cargo is unavailable in this local environment.
