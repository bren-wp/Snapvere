# Snapvere — Wayland compositor acceptance

**Status:** not yet accepted for production. Native headless Sway inventory is automated by quality.yml; no physical or interactive portal run has been recorded for this revision.

| Environment | Required verification |
| --- | --- |
| GNOME / Mutter + xdg-desktop-portal-gnome | Physical monitor mode, logical region, mixed scale, portal consent/revocation, HUD placement and inclusion |
| KDE Plasma / KWin + xdg-desktop-portal-kde | Same, including fractional scales and rotated/mirrored outputs |
| wlroots / Sway + xdg-desktop-portal-wlr | Same, including headless inventory test and interactive physical video stream |

For each environment and Free/Pro, record compositor, portal, PipeWire and GStreamer versions; use 100%, 125%, 150%, 175%, 200% outputs, negative origins, mismatched resolutions, hotplug and display reconfiguration. Compare actual authorized stream dimensions and known pixel-grid source against the selected physical crop. Verify that output-local redaction covers all touched pixels; visual pixelation is not secure deletion and old frames are unaffected. Test pause/resume, revoke authorization, cancel, stale selection, and failed device capture. Verify whether HUD/drawing windows can actually be placed and excluded from the authorized stream. If not, keep gated and design a crop-local preview/control surface instead of claiming exclusion. Capture actual installed Free/Pro screenshots and compare to branding reference on each supported resolution. Keep raw recordings local and do not upload sensitive desktop content.

Acceptance requires exact commit CI results, evidence for every test environment, no unexplained failures, and review of security risks. Headless compositor geometry alone is not end-to-end portal, annotation, privacy or hardware acceptance.

## Isolated real portal inclusion test

Quality CI includes `tools/native/test_wayland_portal.sh` on Ubuntu 26.04. The harness creates a fresh private D-Bus session, virtual Sway outputs, private configuration and PipeWire graph; no host screen, user files, saved portal settings or physical audio devices are used as capture targets. It selects a test output through the actual wlr portal configured only for this disposable session. A synthetic GTK marker is independently checked on the other output, then moved to the captured output. The production portal adapter must detect the marker only after it enters the authorized output. The printed latency covers the move command through PipeWire sample arrival; this is not preview display latency. A failure (including unavailable portal metadata or driver) blocks the CI job, rather than silently accepting an unverified capture. Passing does not authorize showing an ordinary preview window during full-monitor recording. A separate output placement guarantee or supported exclusion API and real GNOME/KDE/wlroots acceptance are still required.

### Headless runner compatibility

The isolated portal inclusion job now uses Ubuntu 26.04 (distribution xdg-desktop-portal-wlr 0.8.1), not Ubuntu 24.04's 0.7.1. Upstream issue https://github.com/emersion/xdg-desktop-portal-wlr/issues/289 documents the older backend's Pixman/DMA-BUF format failure. The normal Linux package and geometry tests remain on Ubuntu 24.04. The portal harness starts the actual packaged backend in the private session with debug logs, verifies D-Bus ownership, records package versions and unmounts only its private document portal FUSE mount before cleanup. All original marker/background, exact authorization metadata and video assertions remain mandatory. The isolated Ubuntu 26.04 job passed on main commit `77507821c7af08232a6fbdda42e6f27e35526bbc` ([job 138841869759](https://github.com/bren-wp/Snapvere/actions/runs/45506179829/job/138841869759)). The log reports `SEPARATE_OUTPUT_MARKER_ABSENT` and `SAME_OUTPUT_MARKER_PRESENT 295365413`. This is isolated synthetic marker evidence, not screen-to-photon latency, physical GPU or legacy portal compatibility.

### Buffer starvation regression (PR #56)

On `3a9b5e0`, job [138878287808](https://github.com/bren-wp/Snapvere/actions/runs/45516825881/job/138878287808) received one valid baseline frame, then the 0.8.1 portal repeatedly reported `out of buffers` and the real stream timed out. Upstream [issue #395](https://github.com/emersion/xdg-desktop-portal-wlr/issues/395) describes a similar freeze, and v0.8.4 contains an upstream starvation fix. CI builds the exact v0.8.4 commit `34153094662acd713241ca6cbbb20003ef67da5f` into runner-local storage, without replacing system binaries or changing shipped dependencies. The test still requires actual portal consent negotiation, background identity and three consecutive marker samples on the authorized output. The first marker timestamp is reported only after sustained samples are confirmed. This mitigation is pending CI verification; 0.8.1 and physical desktop compatibility remain unaccepted. No timeout, consent, geometry or production preview safety gate is relaxed.

### Damage-driven baseline (PR #56)

On `07f567f`, [job 138887559655](https://github.com/bren-wp/Snapvere/actions/runs/45519491411/job/138887559655) negotiated an authorized stream and allocated buffers but received zero valid frames before the existing three-second watchdog. The captured output was static while only the separate marker output repainted. The next isolated test uses a second GTK window repainting two independently verified blue shades on the captured output. Both shades must arrive through the production portal adapter before moving the magenta marker, then three consecutive marker samples must arrive. This tests damage-driven delivery without extending production watchdogs or relaxing authorization, geometry, or pixel checks. The cause is a hypothesis pending native CI.

### Confirmed upstream frame lifetime protocol error (PR #56)

On `70d4321`, [job 138889079447](https://github.com/bren-wp/Snapvere/actions/runs/45519943300/job/138889079447) independently verified the animated fixture and negotiated the authorized stream. The 0.8.4 backend transitioned from STREAMING to PAUSED and back, then reported `session already has a frame object`, followed by `wl_display_dispatch failed: Protocol error`, backend death and consumer broken-pipe errors. Upstream [5724a432](https://github.com/emersion/xdg-desktop-portal-wlr/commit/5724a432fc95690aef19e55e62178d71b60d0cbb) explicitly fixes this exact error by cancelling the in-flight frame whenever its PipeWire buffer is dropped. [162463ab](https://github.com/emersion/xdg-desktop-portal-wlr/commit/162463aba4f0e97b7003f5a9b4b6b9080897c134) also fixes first-frame scheduling on still outputs. Both are included in the released v0.9.0 revision `8388b8a6214470462146840e92909aff5983eeac`, now pinned for the isolated CI backend instead of v0.8.4. All animated baseline, sustained marker, exact geometry, session revocation and fail-closed checks remain unchanged. The new revision is pending CI; no distribution or physical desktop acceptance is inferred, and the installed application does not replace the user's portal.

### Consumer buffer recycling investigation

On `c90fe2f`, [job 138890290950](https://github.com/bren-wp/Snapvere/actions/runs/45520302637/job/138890290950) no longer reported the duplicate-frame Wayland protocol error, but portal v0.9.0 repeatedly ran out of buffers after one explicitly corrupted sample. No valid frame arrived. PipeWire 1.6.2's GStreamer copying path can recycle under the PipeWire loop lock (upstream [30ff8da](https://github.com/PipeWire/pipewire/commit/30ff8da174121567c06a576bf2a83e71779ee991)); this is a plausible contributor, not a proven cause of this run. The adapter now restricts packed raw system-memory caps and detaches a bounded deep copy at the source pad, outside the internal dequeue lock, before conversion or downstream queuing. A regression fixture checks padded frame copying and absence of parent-buffer references. Isolated QA enables source debug logs to distinguish producer starvation from consumer recycling. No authorization or valid-frame watchdog is relaxed. Native CI is required before claiming resolution.
