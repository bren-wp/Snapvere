SNAPVERE PRIVATE SHARING — English deployment
Extract all files directly into the snpv.re document root, including .htaccess.
Requires PHP 8.1+ (64-bit), Apache 2.4 with mod_rewrite, HTTPS and a private writable directory outside every web document root. PHP SAPI must provide Authorization headers. Set PHP post_max_size above 16 MiB. No database or Node process.
The viewer opens immediately. Before uploading from Snapvere, run php setup.php in the hosting terminal as the same user as PHP-FPM. It creates private storage and a random signing secret only if absent, then prints a one-hour single-use upload code. Run it again for another code. Never publish the key or code. SNAPVERE_SHARE_STORAGE may point to a dedicated private directory; keep the same path and key for upgrades. If the host forbids writing outside the document root, use a host-supported private directory instead. Do not put media or keys inside the public root.
The PHP service supports the desktop's current upload, recover, revoke and media range API (16 MiB limit, 2 GiB conservative quota). Only use one deployment backend per storage directory; the PHP and Node storage layouts differ. Never overwrite or migrate existing shares blindly. Expired shares are denied but retained pending operator cleanup. No automatic installation, account provisioning, password protection or resumable large file upload. HTTPS/DNS and live hosting acceptance are required.
