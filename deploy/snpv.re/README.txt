SNAPVERE PRIVATE SHARING — English deployment
Extract all files directly into the snpv.re document root, including .htaccess. No setup page, CLI setup, account, database or Node process is required. PHP 8.1+ (64-bit), Apache 2.4 with mod_rewrite, HTTPS and a private writable directory outside every web document root are required. PHP SAPI must forward Authorization headers; post_max_size must exceed 16 MiB.
On the first authorized grant request the service creates its own private directory and random secret under the PHP account's home. If the hosting account has no safe writable home, configure SNAPVERE_SHARE_STORAGE to a private absolute path outside every public root. Do not copy any old key or media into the public root. Preserve the existing private path/key when upgrading; if the previous deployment used a different private path, configure that path explicitly after verifying it is private. Never silently migrate or re-key existing shares.
The current app requests a one-use grant automatically after native consent. Anonymous issuance is limited to 4 requests per connection IP and 60 globally per hour, with 16 MiB per upload and a 2 GiB conservative storage quota. This is not account authentication. Expired, recognized shares and replay markers older than 25 hours are cleaned in bounded batches (up to 16 entries per grant or upload), under the exclusive storage lock. Unknown, incomplete and malformed records are preserved; an active download may finish after expiry. This is request-driven cleanup, not guaranteed timed deletion when the service is idle. Host-side rate limits, abuse reporting, capacity monitoring, independent retention monitoring and backup policy remain necessary before public production operation. No automatic upload, password protection or resumable large file upload. The PHP and Node storage layouts differ; never point them at the same store. No credentials are included in this archive.

The PHP server supports an authenticated resumable-upload protocol at /api/v1/shares/resume/{begin,status,chunk,finish,abort}. A begin request binds one existing one-use grant to media type, exact length, TTL and full SHA-256. Chunks are 256 KiB (last chunk shorter), committed in order; an identical retry is idempotent. Status returns the confirmed offset. Finish verifies the full digest and media signature before publishing, and existing recover handles lost final acknowledgements. Abort consumes the grant. Current desktop still uses the original upload API; desktop resume UI and native integration are pending. Limit remains 16 MiB; final assembly temporarily requires extra storage. Expired recognized sessions are reclaimed on new begin requests, while malformed/interrupted unknown records are preserved for review. The Node service does not yet implement this protocol.
